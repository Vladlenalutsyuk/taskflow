# Архитектура TaskFlow

## 1. Описание проекта

TaskFlow — система управления задачами с канбан-досками.

Система позволяет создавать доски, распределять задачи между
участниками, отслеживать статусы и учитывать затраченное время.

Вариант №9 — «Система управления задачами (Task Tracker / Kanban)».

## 2. Роли и сценарии использования

Роль пользователя определяется отдельно для каждой доски.
На одной доске пользователь может быть руководителем,
а на другой — исполнителем.

### Общие действия

- Входить в систему с использованием электронной почты и пароля.
- Просматривать доски, участником которых является пользователь.
- Просматривать задачи на доступных досках.

### Руководитель проекта

- Создавать доску и становиться её руководителем.
- Добавлять зарегистрированных пользователей на доску.
- Создавать и редактировать задачи.
- Назначать исполнителей из числа участников доски.
- Устанавливать сроки выполнения.
- Управлять статусами задач на доске.
- Просматривать записи о затраченном времени.

### Исполнитель

- Просматривать назначенные задачи.
- Изменять статус назначенной задачи.
- Добавлять записи о времени, потраченном на назначенную задачу.
- Просматривать свои записи времени.

### Пример сценария

1. Руководитель создаёт доску «Разработка сайта».
2. Добавляет на неё исполнителя.
3. Создаёт задачу «Сверстать страницу входа».
4. Назначает исполнителя и срок выполнения.
5. Исполнитель переводит задачу в статус «В работе».
6. Записывает затраченное время — 60 минут.
7. После выполнения переводит задачу в статус «Готово».

## 3. Архитектура приложения

Используется монолитная архитектура: бизнес-логика
реализуется в одном серверном приложении.

Основные контейнеры:

| Контейнер | Назначение | Технология |
|---|---|---|
| Веб-клиент | Отображение досок и задач, отправка запросов | React |
| Сервер приложения | Проверка прав, обработка запросов и бизнес-логика | Node.js, Express |
| База данных | Хранение пользователей, досок, задач и записей времени | PostgreSQL |

Веб-клиент взаимодействует с сервером через REST API.
Данные запросов и ответов передаются в формате JSON.

Сервер обращается к PostgreSQL с помощью SQL-запросов.
Прямой доступ веб-клиента к базе данных отсутствует.

Redis и очередь сообщений на данном этапе не используются.

## 4. Сущности базы данных

Во всех таблицах первичный ключ id имеет тип BIGINT.

### users — пользователи

| Поле | Тип | Ограничения и назначение |
|---|---|---|
| id | BIGINT | PRIMARY KEY |
| name | VARCHAR(100) | NOT NULL, имя пользователя |
| email | VARCHAR(255) | NOT NULL, UNIQUE |
| password_hash | TEXT | NOT NULL, хеш пароля |
| created_at | TIMESTAMPTZ | NOT NULL, DEFAULT now() |

Пароли хранятся только в виде хешей.

### boards — доски

| Поле | Тип | Ограничения и назначение |
|---|---|---|
| id | BIGINT | PRIMARY KEY |
| name | VARCHAR(150) | NOT NULL, название доски |
| description | TEXT | Описание, может отсутствовать |
| created_at | TIMESTAMPTZ | NOT NULL, DEFAULT now() |

### board_members — участники досок

| Поле | Тип | Ограничения и назначение |
|---|---|---|
| id | BIGINT | PRIMARY KEY |
| board_id | BIGINT | NOT NULL, FOREIGN KEY → boards.id |
| user_id | BIGINT | NOT NULL, FOREIGN KEY → users.id |
| role | VARCHAR(20) | NOT NULL, CHECK: manager или executor |

Пара (board_id, user_id) уникальна:
пользователь не может дважды вступить на одну доску.

При создании доски сервер добавляет её создателя
в board_members с ролью manager.

### statuses — статусы задач

| Поле | Тип | Ограничения и назначение |
|---|---|---|
| id | BIGINT | PRIMARY KEY |
| board_id | BIGINT | NOT NULL, FOREIGN KEY → boards.id |
| name | VARCHAR(50) | NOT NULL |
| position | INTEGER | NOT NULL, CHECK: position >= 0 |

Пары (board_id, name) и (board_id, position) уникальны.

При создании доски добавляются статусы:
«К выполнению», «В работе», «Готово».

### tasks — задачи

| Поле | Тип | Ограничения и назначение |
|---|---|---|
| id | BIGINT | PRIMARY KEY |
| status_id | BIGINT | NOT NULL, FOREIGN KEY → statuses.id |
| assignee_id | BIGINT | FOREIGN KEY → users.id, может отсутствовать |
| title | VARCHAR(200) | NOT NULL |
| description | TEXT | Может отсутствовать |
| due_at | TIMESTAMPTZ | Срок выполнения, может отсутствовать |
| created_at | TIMESTAMPTZ | NOT NULL, DEFAULT now() |

Доска задачи определяется через её статус:
tasks.status_id → statuses.board_id.

Сервер проверяет, что исполнитель является участником
соответствующей доски. При смене статуса сервер проверяет,
что новый статус принадлежит той же доске.

### time_entries — записи затраченного времени

| Поле | Тип | Ограничения и назначение |
|---|---|---|
| id | BIGINT | PRIMARY KEY |
| task_id | BIGINT | NOT NULL, FOREIGN KEY → tasks.id |
| user_id | BIGINT | NOT NULL, FOREIGN KEY → users.id |
| minutes | INTEGER | NOT NULL, CHECK: minutes > 0 |
| comment | TEXT | Может отсутствовать |
| created_at | TIMESTAMPTZ | NOT NULL, DEFAULT now() |

Каждая запись фиксирует автора и количество затраченных минут.
Общее время задачи вычисляется суммированием записей.

## 5. Связи между сущностями

- users и boards: связь M:N через board_members.
- boards и statuses: связь 1:N.
- statuses и tasks: связь 1:N.
- users и tasks: связь 1:N по назначенному исполнителю.
  У задачи может не быть исполнителя.
- tasks и time_entries: связь 1:N.
- users и time_entries: связь 1:N.

## 6. Нормализация

Схема спроектирована в третьей нормальной форме (3НФ):

1. Поля содержат атомарные значения, повторяющиеся группы отсутствуют.
2. Неключевые поля зависят от первичного ключа целиком.
3. Отсутствуют транзитивные зависимости неключевых полей от ключа.

Имя исполнителя и название статуса не копируются в задачи:
они хранятся в отдельных таблицах.

Доска задачи определяется через статус, поэтому board_id
не дублируется в tasks.

Общее затраченное время не хранится в tasks,
а вычисляется по time_entries.

## 7. Индексы

PRIMARY KEY и UNIQUE создают соответствующие уникальные индексы.

Дополнительно предусматриваются индексы:

- board_members(user_id) — поиск досок пользователя;
- statuses(board_id) — поиск статусов доски;
- tasks(status_id) — получение задач по статусу;
- tasks(assignee_id) — получение задач исполнителя;
- time_entries(task_id) — получение записей времени задачи;
- time_entries(user_id) — получение записей времени пользователя.

Уникальный индекс board_members(board_id, user_id)
также используется для поиска участников по board_id.
